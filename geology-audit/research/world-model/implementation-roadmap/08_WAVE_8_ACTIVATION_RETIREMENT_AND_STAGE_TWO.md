# Wave 8 — Activation, Legacy Retirement, and Stage 2

## Goal

Require evidence before causal cutover, preserve rollback, and begin reference generation only after the causal system can explain itself.

## C30 — Full causal audit pack and Stage 2 readiness diagnostics

### Purpose

Assemble the evidence required before any user-facing causal activation.

### Add

- causal dependency graph export;
- event timeline;
- graph, field, layer, ledger, confidence, and contradiction exports;
- full-globe, opposite-hemisphere, polar, seam, continental, regional, and local views;
- bedrock, deposits, water, ice, physical surface, and rendered surface separation;
- legacy-versus-causal same-seed packs;
- controlled one-variable sweeps;
- same-premise/different-history comparisons;
- multi-seed diversity packs;
- earliest-failure report;
- provisional metrics without premature numeric gates.

### Done when

- major visible features have provenance;
- missing causal state is reported explicitly;
- ledgers have no unexplained critical residuals;
- human review can identify the earliest failed stage;
- outputs required by the Stage 2 coverage matrix can be exported.

## C31 — Causal-active opt-in release

### Purpose

Allow explicit testing of the complete causal pipeline while preserving legacy fallback.

### Entry requirements

- C01–C30 merged and passing;
- save/load migration stable;
- determinism proven;
- performance and storage budgets accepted;
- visual review shows clear causal improvement;
- no known critical authority inversion or contradiction failures.

### Add

- developer/user opt-in for `CAUSAL_ACTIVE`;
- beta labeling and schema metadata;
- legacy fallback;
- comparison export;
- no automatic reinterpretation of existing worlds.

### Done when

- new causal worlds generate, save, load, edit, simulate, and render;
- legacy worlds remain usable;
- mode changes cannot absorb authored terrain;
- every release candidate includes the audit pack.

## C32 — Default cutover and legacy patch retirement

### Purpose

Make causal generation the default only after repeated evidence proves it.

### Entry requirements

- explicit user authorization;
- successful multi-seed and visual review;
- no unresolved critical contradiction or ledger failures;
- rollback tested;
- Stage 2 plan ready.

### Add/change

- set causal pipeline as default for new worlds;
- retain legacy save/load and fallback support;
- retire or demote legacy terrain-authority passes one at a time;
- preserve replacement evidence for every removed pass;
- archive obsolete diagnostics only after causal replacements exist;
- document changed generation expectations.

### PR #118 treatment

At this point, decide explicitly whether PR #118 should be:

- closed as superseded;
- mined for bounded variation or tests;
- rebased for a narrowly retained component;
- preserved only as historical visual evidence.

No automatic merge or closure.

### Done when

- no hidden noise-first fallback controls new causal worlds;
- retired passes have named replacements and evidence;
- old saves remain supported or safely migrated;
- rollback can restore legacy default without data loss.

## C33 — Stage 2 reference-generation foundation

### Purpose

Begin reference generation only after causal implementation and separate explicit approval.

### Add

- Stage 2 case registry from the complete coverage matrix;
- case metadata schema;
- project-generated reference provenance;
- licensing-register integration;
- positive, threshold, interaction, temporal, exception, analogue, planetary-regime, and failure cases;
- review workflow;
- versioning and supersession;
- no hard numeric CI gates until cases are calibrated.

### Required project-generated metadata

- case ID;
- seed;
- commit and schema;
- planetary premise;
- regime/history;
- process branches and confidence;
- scale views;
- expected and forbidden signatures;
- review status.

### Licensing rule

External images, maps, DEMs, mission products, simulation frames, and datasets remain blocked unless the exact asset rights are recorded.

### Done when

- references cannot become self-justifying authority;
- every asset is traceable and licensed appropriately;
- cases cover positive and negative evidence;
- Stage 2 begins only after explicit approval.

## Wave 8 final gate

Causal generation may become default only when:

- it is causally explainable;
- it is deterministic;
- it is save/edit/sim safe;
- it is visually better across seeds and scales;
- it preserves rollback;
- the user explicitly approves cutover.

Stage 2 may begin only after a second explicit approval.
